# 用户交互界面中文化

2026-10-13：用户已确认工程审查方案并授权按任务创建 Issue、开发分支及 PR。最终执行约束：开发完成只做 review skill，自动提交正式 PR；需要集成验证时在 60 上做 QA skill。其他测试不自行新增或运行，通用仓库测试要求不能覆盖此明确指令。

## 用户场景

公司内部管理员使用中文配置项目、接入已有数据源、管理图层与权限；使用者以中文查看地图、操作发行包内置工具、阅读提示与界面内帮助。二次开发人员可切换 English 排查问题。

## 要求

- FR1：发行包所有软件提供的用户交互文字，包括标签、提示、错误、弹窗、ARIA 与界面内帮助，应提供规范简体中文。
- FR2：默认中文，可切换 English；语言切换不丢失未保存输入、绘图状态和视角。
- FR3：技术标识、配置键/枚举值、接口路径、坐标参考系、代码和原始业务数据保持原值。
- FR4：统一 canonical 字典及术语表；已有生成机制从源元数据生成，不能手改生成输出。
- FR5：原有英文交互继续可用；旧 API 状态和 message 保持兼容，翻译提示只允许白名单增量字段。
- FR6：中文语句准确、通顺、正规；人工校核语境，不能把自动替换当作完成。

## 成功标准

所有登记界面的中文文案审核通过；审查中的 R1–R18 作为必要 QA 的观察依据，不授权自行增加测试脚本。开发后只执行 review skill，必要集成 QA skill 在 60 隔离副本完成，原始配置和数据不变。每项开发完成经 review 后直接提交正式 PR。

工作仅涉及 UI 显示；不新增连接器、不翻译日志/独立开发文档、不重做地图产品界面。
