关联设计：[设计方案](mmgis-ui-zh-cn.md)；[验收计划](mmgis-ui-zh-cn-test-plan.md)。

本次沿用用户确认的完整 UI 范围，按用户要求停止细粒度问询。下列架构选择是审查建议，不冒充用户逐项批准。源代码证据均来自正式 tag **5.2.24**，不能用当前 zh-CN 分支的 5.4.4 行号替代。运行环境已核实 Ubuntu 24.04.5 LTS、MMGIS 4.2.34-20260328；官方 latest 镜像标签未对应最新正式发行。

## 架构审查：6 项

| 编号 | 证据及风险 | 建议与验收 |
|---|---|---|
| A1 版本基线 | 部署 4.2.34、正式发行 5.2.24、Fork development 5.4.4 三者不同。直接混用会漏改工具或迁移错误。 | 推荐以正式 5.2.24 建独立实施分支，先验证英文原版；保留现有分支历史。版本选择待整体审阅。 |
| A2 身份与文案 | Toolbar.jsx:282 的 ID 和 :325 模块查找依赖 tool.name，ToolController_.js:61 同样依赖名称。 | 保留工具 ID、枚举值和配置键；单独 displayName/messageKey。中英文点击必须打开同一工具，数据保存值一致。 |
| A3 多渲染入口 | Modal/Modal.jsx:119–120 创建独立 React 根；configure 使用 React 17，地图使用 React 18，认证使用传统 JS/Pug。 | 统一维护字典，构建时生成三份资源；每个窗口独立 i18next instance，各 React 根显式 Provider；传统节点显式订阅与释放。切换不能重建绘图或丢失表单。 |
| A4 元数据驱动 | Info/plugin.json:28–30 含英文字段说明；Maker.js:1084–1109 已分离部分 label/value，但 searchdropdown:1145–1173 直接保存值。 | 为源 plugin 元数据增加稳定 UI 键；各控件分开适配。不得翻译保存值、动态数据值，也不能盲目将字符串数组改为对象数组。 |
| A5 提示协议 | public/adminlogin.js:89 直接显示 data.message；Users/routes/users.js:42–47 返回英文密码错误。 | 保留旧状态及 message，增量提供白名单 messageKey/messageParams；本地校验、HTTP、WebSocket 均纳入。未知错误显示中文概要并允许展开原始技术详情。 |
| A6 资源和发布 | 帮助按 key 请求 Markdown；两个前端构建根分开；现有 Docker/CI 未覆盖 zh-CN 发布分支。 | 构建前冻结 resource-index，两个前端构建后核验最终 manifest，避免自哈希循环。镜像包含认证脚本、帮助和服务端资源，固定 digest；升级及回滚先在独立副本演练。 |

选择理由：共享 canonical 字典减少重复维护；按既有前端边界生成资源避免 eject 或跨目录导入；显式显示适配比全局 DOM 文本替换更容易保持行为与配置兼容。

```text
canonical 字典 + 插件 UI 键 + 中文帮助
                 |
          generate / legacy build
                 |
     冻结 resource-index（不依赖最终 bundle）
        /                |                 \
 地图 generated    configure generated    API generated
      |                   |                 |
 地图构建             后台构建            Pug 固定翻译器
        \                /                 /
           最终 manifest 核验 -> 镜像

URL lang > 合法 locale cookie > zh-CN
                   |
          窗口内语言实例与订阅
      React 多根 / 传统节点 / 动态元数据
                   |
       更新显示；保留焦点、编辑值与绘图状态
```

实施时在 locale 同步模块和构建资源生成器加入上述状态/依赖注释；普通翻译组件不增加冗余图示。

## 代码质量审查：3 项

- Q1：只修改 plugin.json 等源元数据。API/updateTools.js:144–148、180–186 会生成 toolConfigs.json 与 pre/tools.js，手改输出会在下一次构建丢失。生成器必须幂等并检查字典、参数占位符和 UI 键唯一性。
- Q2：显示入口不能统一使用未转义 HTML。稳定版 Maker.js:527 的描述走 dangerouslySetInnerHTML；React 普通文本用默认转义，传统界面用 textContent，确需格式的帮助/描述用现有 DOMPurify。翻译参数不接受任意 HTML。此项是本次新显示路径的安全要求，不扩展成全仓安全改造。
- Q3：日期、数字用 Intl；统一术语表与缺失键审计。界面标签、ARIA、工具提示、空状态、错误、界面内帮助和嵌入第三方控件全部登记。不可用工具也要中文说明，不能以外部服务未配置为由跳过界面验收。

## 性能审查：2 项

- P1：不使用全局 MutationObserver 扫描页面，不在每个地图要素上重复查找字典。翻译按 UI 文案键缓存，控件订阅在销毁时释放；切换只更新显示。
- P2：初版 UI 字典随本地 bundle，帮助按需读取。建议预算：每套前端新增压缩资源不超过 150 KiB；同环境首次可用时间增量同时不超过 10% 和 150 ms；语言切换 P95 小于 100 ms。均为待测目标，超限先定位再调整，不声称当前达到。中文字体、地图瓦片缓存和网络条件必须一致。

本次无新增数据库查询路径，不改变地图瓦片/数据接口；仍检查语言切换未意外触发重复数据请求。

## 已有能力与复用

复用两个既有前端构建、plugin 元数据生成、Maker 部分 label/value 分离、Help 的 DOMPurify、现有测试工具与 Docker。数据接入、图层管理、详情展示已属于上游能力；本轮只为它们的交互表面增加翻译，不重新实现数据连接器。

## 不在范围内

- 源码注释、服务日志、独立开发文档：用户要求其他内容无需中文。
- 技术键、URL、原始业务数据和原始导出数据：翻译会破坏接口或内容语义。
- 新数据连接器、重做地图界面、私有插件功能：与发行包 UI 汉化是不同工作。
- 全仓框架升级、CRA eject、全局 DOM 替换、多语言翻译平台：初版无必要。
- arm64 发布：现有交付服务器为 amd64。
